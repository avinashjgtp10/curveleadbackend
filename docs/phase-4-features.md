# Phase 4 — Assignment, integrations and messaging

Branch: `fix/phase-4-features`. Includes the completed local Phase 3 work and the current merged Phase 2 baseline. Publish/merge Phase 3 before this phase. No production migration, live message send or deployment was performed.

## Changes and entry points

- **Settings → Assignment:** existing source/campaign rules now match city (falling back to location), can round-robin selected staff, and have a workspace fallback assignee. First matching rule wins. Assignment and cursor changes happen in the ingestion transaction under a workspace lock, covering manual, API, Meta, Google, WhatsApp and import creation. Explicit assignees and deduplicated existing leads are preserved. Activities name the assignee and rule. Existing optional sequence enrollment and assignment notifications remain.
- **Dashboard integration health:** fifteen-minute checks record Facebook/WhatsApp credential validity and Google lead-form webhook-key validity. New submissions, including duplicate submissions, record receipt time. Invalid credentials and inactivity beyond the configured threshold (24 hours by default) produce a banner and administrator notification, deduplicated for 24 hours. Network errors do not declare a valid token invalid. Google Ads in this repository uses incoming lead-form webhook keys, not OAuth lead polling.
- **Settings → Messaging:** enable CAPI, configure Qualified/Won event names and view the event queue/status. Existing custom pipeline mappings remain supported. Database transitions queue events transactionally, including bulk and automated stage changes. The worker uses stable event IDs and original UTC event times, hashed email/phone and Meta lead IDs. Five delivery attempts are allowed. CAPI is off until explicitly enabled; dataset/token remain in Integrations.
- **Inbound replies:** ordered keyword, first-message and outside-business-hours rules send text or approved templates. Text requires an open 24-hour session. Current inbound template rules support approved body-only templates without variables; use text with existing lead placeholders for personalized replies inside a session. Business hours use their configured timezone, including overnight ranges. Opt-outs and human takeover suppress replies. Incoming provider retries are claimed atomically with message storage; receiving-number identity scopes sender lookup to the workspace.
- **Bulk WhatsApp:** use filtered Leads, select recipients (existing maximum 250), select an approved template, map variables and send/schedule. At execution, templates are checked again and their authoritative body is stored. Opt-outs, configured opt-in requirements, recipient ownership and rolling quota are enforced. Meta's live messaging tier is used when available; a verified workspace cap is the fallback and can impose a lower limit. Local counting is conservative across workspace outbound traffic; Meta remains authoritative for usage from other tools and additional restrictions. **WhatsApp → Messages → Broadcasts** shows sent, delivered, read, replied and failed counts, including later delivery failures. Replied means a later inbound message from that campaign recipient.
- **Inbox:** `/` suggests canned replies configured in Settings → Messaging. Tags remain editable; custom attributes are now editable in the contact panel. “Human took over” pauses AI, inbound/away replies and scheduled sequence sends until resumed. Existing administrator inbox view covers all team chats; staff remain assignment-scoped. New manual/broadcast template messages store the actual rendered body and display humanized names. Historical messages missing their original variables retain the existing explicitly labeled reconstruction.
- **Content views:** newly shared brochure links and quotation online/PDF links are unique tracked URLs. The first request to each link records an activity, notifies the assigned rep and advances cold → warm → hot. Repeated requests to the same link do not duplicate these effects. Link requests do not establish the visitor's identity; existing old direct URLs are unchanged.
- **CSV/Excel import:** server preview supports column mapping, E.164 phone normalization, existing and within-file duplicate detection. Presets cover Privyr, AiSensy and Interakt common headers. Mapping changes require revalidation; invalid rows block the UI import action. Preview performs no writes. Actual ingestion rechecks dedupe at commit time. CSV export uses the same tenant/staff/search/filter logic as the list, includes hidden-stage exclusions, pages through all results, exports UTC timestamps and protects spreadsheet formula cells.
- **Settings → Developer:** generate/regenerate a show-once API key; new keys are stored as hashes. Existing keys remain accepted until rotated. Generated embed snippets use a placeholder for a newly hashed key: paste the saved key before use. Configure outgoing lead.created, lead.stage_changed and lead.won webhooks; secrets appear once and are encrypted at rest. Delivery logs show attempts/status/errors. Only public HTTPS/IPv4 destinations on port 443 are accepted; DNS is checked and pinned per attempt, redirects are not followed. Recipients should verify HMAC-SHA256 over `timestamp + "." + raw_body`, using `X-CurveLead-Timestamp` and `X-CurveLead-Signature`, and deduplicate `X-CurveLead-Delivery`. Delivery is at least once with up to five attempts.

## Migration and rollout

1. Deploy all prior migrations, including Phase 3 and the existing assignment, Meta CAPI, scheduled broadcast, Google lead-form, custom-field and notification schemas.
2. Apply **backend/models/migration_phase4_features.sql** before deploying either application. This transactional, repeatable migration adds assignment staff IDs, integration health, tracked links, inbound claims, broadcast reports/quota reservations, webhook delivery outbox and CAPI queue. It adds lead-transition and duplicate-submission triggers. No backfill or manual data edits are required. Schedule DDL for a maintenance window on busy tables.
3. Set **META_APP_SECRET** to the Meta app secret that signs WhatsApp deliveries. POST `/api/whatsapp/webhook` now verifies `X-Hub-Signature-256` against the exact raw request body. Missing configuration returns 503; invalid signatures return 401. GET webhook verification remains compatible.
4. Keep `JWT_SECRET` stable for encrypted webhook secrets. Set `API_BASE_URL`/`API_URL` to the public API origin and `FRONTEND_URL` to the application origin for shared links.
5. Deploy backend, then frontend. The existing process schedules the new worker every minute and health checks every fifteen minutes. CAPI/webhook records survive process restarts. Configure CAPI credentials/toggle and verified messaging quota before exercising live sends.
6. If rolling application code back, disable CAPI/webhooks first. Do not drop outbox/audit tables or reverse data writes as part of a routine rollback; preserve them for investigation.

## Manual QA before release

1. Configure two selected staff, source/campaign/city rules and a fallback. Create simultaneous matching leads via manual/API/import; confirm alternating assignees, first-match behavior, fallback and assignment activities. Confirm a duplicate does not create or reassign a lead.
2. Set a short health threshold in a test workspace. Verify inactive integrations produce one administrator alert, a new submission recovers the state, rejected tokens show reconnect guidance, and a transient timeout does not label the token invalid.
3. Enable CAPI with test credentials. Move a Meta lead to Qualified and Won individually and in bulk; verify queued → success or visible failed status. Save an unchanged stage and confirm no extra event. Disable CAPI and confirm new transitions do not send.
4. Send signed test inbound messages for keyword/first-message/away rules, including midnight across a configured business day. Replay the same delivery; confirm one stored message/reply. Test opt-out and human takeover. Confirm text sends fail outside the session and approved template rules behave as documented.
5. Send and schedule a small approved-template campaign with variables, an opted-out lead and a deliberately low quota. Confirm rendered bodies, restricted recipients and failure counts. Deliver read before delivered receipts and confirm read never regresses. Reply and inspect the campaign report.
6. As a rep, use `/` canned replies, edit tags/custom attributes, take over/resume and confirm sequences stop while paused. As admin, inspect other reps' conversations; as staff, verify other assignments remain inaccessible.
7. Share a brochure and quotation. Open online and PDF tracked links, then reload the same link; check one activity/notification/score change per link.
8. Preview each import preset, remap columns, include invalid and duplicate phones, and confirm preview writes nothing. Commit valid rows; check normalization, merge and assignment. Export a filtered search with hidden stages and more than one page; compare IDs/counts and reimport sample phones safely.
9. Generate/regenerate an API key, save the one-time value and test ingestion. Verify the previous key is revoked and no settings response reveals the new raw key. Add a webhook to a controlled public HTTPS receiver; validate signature and delivery IDs, exercise failures/retries and disable it. Private/local destinations must be rejected.
10. Visit every sidebar page with a normal configured workspace; check console/network errors and compare same-period Won/conversion metrics on Dashboard, Reports, Campaigns and Coaching. Check Settings and Inbox on narrow screens.
